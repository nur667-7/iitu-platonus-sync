## 2. Разделение слоев

### Ingestion Layer (Сбор данных)
- **PlatonusClient (`src/platonus.js`):** обращается к закрытому REST API Platonus IITU (`/api/v1/auth`, `/api/v1/journal`, `/api/v1/schedule`), преобразует сырые JSON-ответы в канонические сущности занятий, оценок и пропусков.
- **TeamsClient (`src/teams.js`):** подключается к Microsoft Graph API, загружает сообщения академических команд и чатов, очищает HTML-разметку.
- **TeamsAnalyzer (`src/teamsAnalyzer.js`):** исключает нерелевантные чаты (черный список), классифицирует сообщения по эвристикам (`TASK`, `SCHEDULE_CHANGE`, `EXAM`, `INFO`).

### Classification Layer (Маршрутизация)
- **Fast Router:** не нагружает LLM простыми вопросами (`/today`, `/week`, `/grades`, `/attendance`, `/focus`). Время ответа — менее 1 миллисекунды.
- **Groq LLM Router:** при получении неструктурированного текста вызывает модель `openai/gpt-oss-120b` в режиме строгого JSON-вывода.
- **Question Guard:** гарантирует, что вопросы о дне или истории («Что у меня сегодня?», «Что было сделано вчера?») распознаются как `QUERY` и никогда не порождают мусорных записей в базе задач.

### Task Engine & Resolver
- **Fingerprinting:** из названий извлекаются устойчивые ключи (например, `lab:4` по предмету `Java Spring`).
- **Cross-Source Merge:** если дедлайн объявлен в Teams, а само задание висит в Platonus, TaskResolver объединяет их в единую карточку с ссылками на оба источника.
- **Dual Date Model:** четкое разделение между:
  - `deadline` — крайний срок сдачи преподавателю.
  - `plannedDate` — день, когда студент наметил выполнение.

### Storage Strategy
- **Notion:** пользовательский интерфейс и источник истины по состоянию задач (Kanban / Calendar).
- **Academic Cache (`state.json`):** локальный кэш расписания недели, журнала и посещаемости для ответа за < 100 мс без задержек сети Платонуса.
- **Vercel Stateless Handler (`api/webhook.js`):** серверлесс-функция не зависит от локального диска и работает напрямую через облачные API.
